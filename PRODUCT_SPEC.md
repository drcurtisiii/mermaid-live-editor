# Mermaid View Edit — Product Specification (v1.0.0)

## Purpose

A Windows desktop app to **view and edit Mermaid diagrams** stored as local files, with a live
side-by-side preview. It is a fork of the open-source
[mermaid-js/mermaid-live-editor](https://github.com/mermaid-js/mermaid-live-editor) (MIT),
wrapped as a portable, versioned Windows executable with real file open/save.

## Intended users

Attorneys and staff at The Curtis Law Firm who receive or produce `.mermaid` / `.mmd` diagrams
(e.g. project maps, process maps, timelines generated by Claude skills) and want to read or adjust
them without a browser or a web service.

## Primary workflows

1. **Drag-and-drop view/edit** — drag one or more diagram files onto the desktop shortcut; each
   opens in its own editor window with live preview.
2. **Double-click launch** — opens an Untitled editor; _File > Open_ (multi-select) opens files.
3. **Edit and save** — edit in the code pane (Monaco, syntax highlighting, error markers);
   _Ctrl+S_ saves back to the same file; _Save As_ to `.mmd`, `.mermaid` or `.md`.
4. **Markdown** — a `.md` file's ` ```mermaid ` block is edited in place; the rest of the
   Markdown is preserved. With several blocks, the user picks one.
5. **Export** — PNG/SVG via the editor's _Actions_ panel, or _File > Export SVG_.
6. **Outside changes** — if the file changes on disk (Claude, Dropbox, another editor), an unedited
   window reloads automatically; an edited window asks first.

## Inputs / outputs

- Input: `.mmd`, `.mermaid`, `.txt`, `.md`, `.markdown` (UTF-8, ≤ 5 MB).
- Output: the same file (atomic temp-file + rename, BOM and CRLF/LF preserved), SVG/PNG exports.

## Stored data

- `%LOCALAPPDATA%\MermaidViewEdit\settings.json` — recent files, last folder.
- `%LOCALAPPDATA%\MermaidViewEdit\browser\` — editor state (last diagram, History timeline).
- `%LOCALAPPDATA%\MermaidViewEdit\logs\app.log` — diagnostics (no diagram contents).

## External systems

None required. Network is only used when the user clicks an external link (docs, GitHub) or
loads a Gist. The desktop build **disables** analytics, Mermaid Chart promotions and the
mermaid.ink / kroki.io share-link renderers, so diagram text is never sent out by default.

## Errors and recovery

- Unsupported / missing / oversized files: one summary dialog; valid files still open. If nothing
  opened, the app exits.
- Unsaved edits: Save / Don't Save / Cancel on close. Save failures leave the window dirty.
- Markdown whose mermaid block was removed while open: save refused; Save As offered.
- Updates never interrupt work: missing/malformed/partially-synced manifests are logged and retried.

## Security / privacy

Diagram content may be privileged: nothing is uploaded; the renderer is sandboxed with context
isolation and no Node access; only http(s) links open, and only in the default browser.

## v1 acceptance criteria

- Opens dropped files (multiple, spaces, Unicode, punctuation) in separate windows.
- Edit + save round-trips `.mmd` and `.md` correctly.
- Title shows `… - Mermaid View Edit v1.0.0`.
- Portable `Mermaid View Edit v1.0.0.exe` with embedded icon, versioned desktop shortcut,
  file-based side-by-side updates, build script, tests passing.

## Assumptions

- "Fork it" = a GitHub fork (`drcurtisiii/mermaid-live-editor`) plus a desktop shell in that fork.
- The drag-drop spec's "process files headlessly and exit" pattern is adapted: for a viewer/editor,
  "processing" a dropped file means opening it in an editor window. Windows stay open for editing;
  the app exits only when nothing could be opened.
- One app instance: later launches/drops are forwarded to the running instance (shared browser
  profile must not be used by two processes).
